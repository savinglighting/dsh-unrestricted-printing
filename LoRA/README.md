# 一键炼制 LoRA · 标准交付包

> 本目录是「dsh-unrestricted-printing 一键炼制 LoRA」的**标准文件**：参数标准、数据集模板、验收清单与打包脚本都在这里。
> 插件侧入口是三个工具：`sd_train_lora`（提交/预览）、`sd_train_status`（进度与失败原因）、`sd_lora_list`（成品与调用语法）。

---

## 1 目标与架构

采用**双 LoRA 解耦**：一次炼制产出两个产物，各自只负责一件事。

| 轨道 | 名字后缀 | 只负责 | 推理权重 | 体积 |
|---|---|---|---|---|
| ID-LoRA | `_id` | 面部 / 角色身份（**刻意低秩**，防记忆服装背景） | 固定 **1.0**，不给调节空间 | 8–20 MB |
| Base-LoRA | `_base` | 画风 / 服装 / 场景（LoCon 覆盖卷积层） | **0.3–0.7**，硬上限 0.7 | 30–90 MB |

这样做的收益：换装时只调低或替换 Base，ID 权重一直保持 1.0 —— 脸不漂、衣服能换、画风能换。

> **名字可自定义**：`name` 给公共名（自动得到 `xxx_id` / `xxx_base`）；也可用 `idName` / `baseName` 单独指定某一轨。
> 名字里的 `:` `,` `<` `>` 会被自动清洗（这几个字符会把 `<lora:名字:权重>` 语法撕开）；与已有产物重名时自动版本化 `_v2`，绝不覆盖别人的 LoRA。

## 2 数据规范

- 每轨 **15–30 张**；姿态、角度、光照、表情要有变化，但**面部保持一致**。
- kohya 目录：数据集根目录下 `重复次数_概念名`，图片与**同名 `.txt`** 标注一一对应；可选 `reg` 目录放 5–10 张通用人物图减轻遗忘。
- 素材来源三选一（可混用）：本地目录 / 图片直链 / 参考图。采集会做格式白名单、精确去重、短边检查与来源留痕。
- **自动拆轨**：按构图标签分流 —— 特写/头肩 → ID 轨，半身/全身/场景 → Base 轨；判不清的按缺口交替补齐。也可用 `idSources` / `baseSources` 显式分轨。

### 标注铁律（最容易毁掉一次炼制的地方）

只描述**场景与可变元素**。

- ✅ 正确：`woman in garden, sunlight, green dress, upper body`
- ❌ 错误：`sks woman, <lora:xxx>, my OC Alice in garden`

以下内容一律禁止，出现即被拦截：角色名、身份 token、触发词、作品名/系列名、`<lora:...>` 内联语法。
"出现在**每一张**标注里的非通用词"会被判为疑似身份 token 并**在训练前直接拦下**。

### 训练前硬校验（不通过就不开训）

| 检查项 | 判定 |
|---|---|
| 图片 ↔ 标注配对 | 缺一个就报错（指出具体文件名） |
| 标注为空 | 报错（会学成纯背景） |
| 疑似身份 token | 出现在 100% 标注里 → **拦**；80–99% → 警告 |
| 最短边 | < 512 → 报错，要求先等比放大/裁剪 |
| 脸部特写占比 | ID 轨 ≥ 60%；Base 轨 ≤ 25%（**超限在 Base 轨是硬拦**——这正是 Base 学到身份的主因） |
| reg 图数量 | 给了就不该少于 5 张或多于 10 张（超限警告） |

## 3 训练参数标准

见 `configs/id-lora.json` 与 `configs/base-lora.json`（与代码里的标准同源，改动会由测试拦住）。

| 标准项 | ID-LoRA | Base-LoRA |
|---|---|---|
| 训练模块 | 标准 LoRA | LyCORIS LoCon |
| 算法/卷积 | 无 | `algo=lora`，`conv_dim=4`，`conv_alpha=2` |
| network_dim | 8（过拟合可降 4） | 32（体积过大降 16） |
| network_alpha | 16 | 16 |
| 学习率 | 4e-5 | 7e-5 |
| 最大步数 | 500（过拟合降到 300–400） | 800 |
| 优化器 | AdamW8bit（无 bitsandbytes 时退避 AdamW） | 同左 |
| 分辨率 / 精度 | 512 / fp16 | 512 / fp16 |
| 分桶 / 保存 | enable_bucket，safetensors | 同左 |
| 正则化 | 可选 5–10 张通用人物图 | 同左 |

**硬底线（任何来源都改不了）**：优化器、混合精度、显存档、分桶、保存格式 —— 这些写错就是崩，统一兜住。
**可钳制的用户参数**：dim / alpha / 学习率 / 步数 / 分辨率 —— 越界会被钳到档位护栏内，并把「原值 → 新值」回传给你，不静默改数。

## 4 推理控制

| 场景 | ID 权重 | Base 权重 |
|---|---|---|
| 解耦自检（应只剩"无服装风格的脸"） | 1.0 | 0 |
| 保脸、弱化服装（默认） | 1.0 | 0.3–0.5 |
| 日常稳定档 | 1.0 | 0.4 |
| 完全换装 | 1.0 | 替换 Base 文件 |
| 只保画风、弱化角色 | 0.2–0.3 | 0.5–0.7 |
| 上限 | 1.0 | 不超过 0.7 |

调用语法：`<lora:xxx_id:1.0>` + `<lora:xxx_base:0.4>`（权重按上表取）。

## 5 验收标准

炼制完成后逐条确认（`acceptance/acceptance-checklist.md` 可直接照着勾）：

1. 两个 `.safetensors` 都生成，且都在 SD 的 LoRA 目录里；
2. 推理时能同时加载 ID 与 Base 两个适配器；
3. ID=1.0、Base=0.4 时面部稳定、服装画风受控；
4. Base 权重归零、只加载 ID 时**没有**强烈服装或背景残留；
5. 替换 Base 文件后**面部无明显变化**；
6. 体积符合轻量要求（ID 8–20 MB / Base 30–90 MB）；
7. 训练全程无显存溢出、无混合精度报错；
8. 全量标注不含角色名与身份 token；
9. 插件闭环：炼制完**不需要重启**，参数表里就能勾选到新 LoRA 出图。

## 6 排查清单

| 症状 | 处置 |
|---|---|
| ID 过拟合、脸像贴图 | ID 的 dim 降到 4，或步数降到 300–400；检查素材姿态/光暗多样性 |
| Base 污染面部 | 减少 Base 数据里的脸部特写、增加半身/全身/场景；Base 权重确保 ≤ 0.7 |
| 换装后脸变了 | 查 ID 权重是否误低、Base 是否过高、ID 训练秩是否过高 |
| 只加载 ID 仍带服装背景 | 降 ID 的 dim 或减少步数 |
| 画风细节不足 | 提高 Base 的 dim 或步数（注意体积代价） |
| 成品过大 | Base 的 dim 降到 16，或减少卷积覆盖 |
| 显存不足（`TRAIN_OOM`） | 确认 AdamW8bit + fp16 + enable_bucket + 512；仍不够就降 batch_size 或加 `--lowvram` |
| 缺训练脚本（`TRAIN_SCRIPT_MISSING`） | 用 `GW_TRAIN_SCRIPT` 指向 kohya 的 `train_network.py` |
| 缺依赖（`TRAIN_DEPS_MISSING`） | kohya 训练环境没装全（bitsandbytes 等） |
| LoCon 不可用（`TRAIN_LYCON_UNAVAILABLE`） | 装 lycoris，或把 Base 轨临时降级为 `networks.lora` |
| 标注污染 | 查 `.txt` 是否出现角色名/触发词；用 `bannedTokens` 显式列出角色名 |
| 炼制完参数表看不到 | `sd_lora_list` 看是否已落盘；SD 没启动时刷新会失败但产物已在，SD 下次启动自然能扫到 |

## 8 运行时工作区（不在本目录）

炼制过程的数据集、训练日志、登记表都在 `.lora-train/`（默认在插件目录下，可用 `GW_LORA_TRAIN_ROOT` 改位置）：

- `datasets/<名字>/10_<概念>/` —— 图片 + 同名标注
- `logs/` —— 每轨训练日志（失败原因从这里读尾部）
- `jobs/` —— 每次炼制的状态文件（`sd_train_status` 就是读它）
- `lora-registry.json` —— 成品登记表（名字 / 档位 / dim / 步数 / 体积 / 数据量 / 耗时 / 来源摘要 / 调用语法）
