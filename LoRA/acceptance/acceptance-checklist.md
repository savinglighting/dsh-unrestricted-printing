# 一键炼制 LoRA · 验收清单

> 一次炼制结束后逐条勾。**任何一条不过，就不要拿去正式出图** —— 尤其是第 3、4、5 条（解耦是否干净）。

## A 产物与投递

- [ ] ID 轨 `.safetensors` 已生成，命名符合预期（`<名字>_id`）
- [ ] Base 轨 `.safetensors` 已生成，命名符合预期（`<名字>_base`）
- [ ] 两个文件都在 SD 的 LoRA 目录里（`sd_lora_list` 的 `loraDir` 能看到，且 `onDisk: true`）
- [ ] 登记表里两条记录齐全：档位 / dim / 步数 / 体积 / 数据量 / 耗时 / 来源摘要 / 调用语法
- [ ] 若与已有 LoRA 重名：确认走的是版本化（`_v2`）而不是覆盖

## B 体积与规格

- [ ] ID 轨体积 8–20 MB（明显更大 → ID 秩过高，容易过拟合学服装）
- [ ] Base 轨体积 30–90 MB（更大 → 考虑 dim 降到 16）
- [ ] ID 轨 `network_dim` = 8（或过拟合降到 4）；Base 轨 = 32（或体积过大降到 16）
- [ ] Base 轨 module 是 `lycoris.kohya`，且 conv 参数在位（`conv_dim=4`、`conv_alpha=2`）

## C 解耦质量（最关键）

- [ ] **同时**加载两个适配器可行（ID 与 Base 独立命名、独立控权）
- [ ] ID=1.0、Base=0.4：面部稳定，服装与画风明显受控
- [ ] **Base 归 0、只加载 ID**：输出只剩"无服装风格的脸"，没有强烈服装或背景残留
- [ ] **替换 Base 文件**：面部没有肉眼可见的变化
- [ ] ID 权重保持 1.0 时，换装只靠调低/替换 Base 即可成立

## D 数据合规

- [ ] 全量标注里**没有**角色名、身份 token、触发词、作品名
- [ ] 没有 `<lora:...>` 内联语法残留
- [ ] ID 轨脸部特写占比 ≥ 60%
- [ ] Base 轨脸部特写占比 ≤ 25%
- [ ] 每轨素材 15–30 张，姿态/角度/光照/表情有变化，面部一致
- [ ] （给了 reg 的话）reg 图 5–10 张，且是"通用人物"不是本角色

## E 运行环境

- [ ] 训练全程无显存溢出（无 `TRAIN_OOM`）
- [ ] 无混合精度报错
- [ ] 训练日志已落盘（`logs/`），失败时能读到尾部原因

## F 插件闭环

- [ ] 炼制结束后**不重启**就能在参数表里勾选到新 LoRA
- [ ] `sd_lora_list` 给出的调用语法可直接粘贴（`<lora:名字:权重>`）
- [ ] 训练期间并发生图被 409 拦下，训练结束后自动释放（不是永久锁死）

## 不合格怎么改（速查）

| 不过的条目 | 改法 |
|---|---|
| C 第 3 条（只加载 ID 仍带服装背景） | 降 ID 的 dim 或减少步数，重炼 |
| C 第 4 条（换 Base 后面部变化） | 降 Base 权重到 ≤0.5；Base 数据减少脸部特写 |
| B 体积过大 | Base dim → 16；或减少卷积覆盖 |
| D 特写占比不符 | 补/删素材后重跑（训练前就会被拦） |
| E 显存溢出 | 确认 AdamW8bit + fp16 + enable_bucket + 512；降 batch_size 或加 `--lowvram` |
| F 参数表看不到 | `sd_lora_list` 确认已落盘；SD 没运行时会刷新失败，下次启动自然扫到 |
